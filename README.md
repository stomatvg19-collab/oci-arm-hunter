# oci-arm-hunter

Ловить вільну **Always Free ARM-машину** (VM.Standard.A1.Flex) в Oracle Cloud,
регіон `ca-toronto-1`.

Пробує два розміри: спершу бажані **4 ядра / 24 ГБ**, потім запасні **2 ядра / 12 ГБ**.
Oracle роздає потужності шматками, тому менша конфігурація втискається в залишки
значно легше — а для стенда її вистачає з запасом. Взяти менше не пастка:
безкоштовний ліміт можна витратити як завгодно, і машину потім дозволено збільшити.

## Навіщо

Oracle роздає безкоштовні ARM-потужності з решток: у популярних регіонах вони
розлітаються за секунди, і запит на створення повертає `Out of host capacity`.
Це не помилка налаштування — просто в цю мить вільного слота немає.

Єдиний робочий підхід — пробувати регулярно й довго. Робити це циклом на власному
комп'ютері марно: ноутбук вимикають, а слот може звільнитись серед ночі. Тому
полювання живе тут — GitHub тримає його цілодобово й безкоштовно.

## Як це працює

Один запуск живе **майже 6 годин** (стеля GitHub для завдання) і всі ці години
шле спроби — по дві на цикл, обидва розміри.

Пауза між циклами **адаптивна**. Спокуса довбати частіше не працює: Oracle
відповідає `Too many requests for the user` і навіть не дивиться на вільні
потужності — спроба згорає даремно. Заміряно на практиці з паузою 20 секунд.
Тому базова пауза — хвилина, а на кожне обмеження вона подвоюється (до 10 хвилин)
і повертається назад, щойно Oracle знову відповідає по суті.

Спершу тут стояв cron `*/5` із коротким завданням, але виявилось, що **розклад
GitHub — best-effort**: часті інтервали він відкладає або пропускає під
навантаженням. Заміряно на практиці — за 23 хвилини не спрацював жодного разу.
Тому логіка перевернулась: працює довгий запуск, а розклад (раз на 2 години)
лишився тільки сторожем, який будить наступний, коли попередній добіг чи впав.
Обмеження `concurrency` тримає рівно один активний запуск, а другий чекає в
черзі й підхоплює естафету одразу після нього.

Коли машину спіймано:

1. створюється **Issue** з IP-адресою та командою підключення — GitHub одразу
   надішле лист на пошту;
2. воркфлоу **сам себе вимикає**, щоб не крутитись далі даремно.

Якщо машина вже існує, запуск завершується за секунди — перевірка йде перед
будь-якою спробою створення.

## Що всередині

| Тип | Ім'я | Що це |
|---|---|---|
| Secret | `OCI_KEY` | приватний ключ API Oracle |
| Secret | `OCI_USER` | OCID користувача |
| Secret | `OCI_FINGERPRINT` | відбиток ключа |
| Secret | `OCI_TENANCY` | OCID тенансі |
| Variable | `SUBNET_ID` | підмережа, створена заздалегідь |
| Variable | `IMAGE_ID` | образ Ubuntu 24.04 aarch64 |
| Variable | `AVAILABILITY_DOMAIN` | домен доступності |
| Variable | `SSH_PUBKEY` | публічний ключ для доступу до машини |

Репозиторій публічний **лише заради безлімітних хвилин GitHub Actions**
(приватним репозиторіям дають 2000 хв/міс — цього вистачило б менше ніж на дві доби).
Жодних секретів у коді немає: вони лежать у Secrets і в публічний доступ не потрапляють.
